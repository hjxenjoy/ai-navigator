# 6.7 场景 Playbook·信息处理

从这节起进入**分场景实战**：每个场景给"可套用模板 + 注意点 + 正反例"。先讲最常见的信息处理四件套：分类、抽取、摘要、改写/翻译。它们的共同特点是**有相对客观的标准**，所以提示要往"稳定、可解析"上使劲。

## 分类 / 打标签

**模板：**

```
你是{领域}标注员。把下面的{对象}归入以下类别之一：
- 类别A：{一句话定义}
- 类别B：{一句话定义}
- 其它：不属于以上的

参考例子：
输入：{例1} → {类别}
输入：{例2，故意放一个边界/易混的} → {类别}

只输出类别名，不要解释。
对象：{input}
```

**注意点：**
- **类别定义要清晰、互斥**——边界模糊是错分的头号原因
- Few-shot 里**一定放一个易混 case**，把边界掰正（[6.3](./reasoning)）
- 留一个"其它/无法判断"类，别逼它在不合适的类里硬选
- 要确定性：`temperature` 调低（[6.5](./reliability)）

❌ "判断这条评论是好是坏" → 标准模糊
✅ 给出"好评/中评/差评"各自定义 + 边界范例 + 只输出类别

## 信息抽取（结构化）

**模板：**

```
从下面的{文本}中抽取信息，按此 JSON 输出：
{"name": string, "age": number|null, "tags": string[]}

规则：
- 找不到的字段填 null（数组填 []），不要编造
- 只输出 JSON，不要其它文字

文本：{input}
```

```javascript
// 配合强制 JSON（6.4）
response_format: { type: "json_object" }
```

**注意点：**
- **明确给出字段 schema 和类型**，缺失填 `null`——这一句能挡掉大量"硬编一个值"
- "不要编造"是关键约束（抽取最怕它脑补）
- 拿到结果 try-catch 解析；字段不全要兜底
- 字段多、要求高、量大 → 考虑 [微调一个抽取模型](/ch5-deep-dives/finetuning-cases)（比堆提示更稳）

## 摘要

**模板：**

```
请把下面的文章总结成{3 个要点 / 100 字内 / 一句话}，面向{读者}。
要求：
- 只基于原文，不要加入原文没有的信息
- 保留关键数据和结论
- {可选：突出 X 角度}

文章：
"""
{input}
"""
```

**注意点：**
- **指定长度和角度**：是"给老板看的一句话结论"还是"技术要点清单"？不说清它会给你不上不下的一坨
- **强调忠实原文**：摘要最常见的幻觉是"加戏"——总结出原文没说的东西
- 长文章注意 [上下文限制和中间迷失](/ch1-llm-engineering/)，必要时分段摘要再合并
- 给"结构"（几个要点）比给"字数"更可控（[6.4](./output-control)）

## 改写 / 润色 / 翻译

**模板（改写润色）：**

```
你是{中文技术编辑}。把下面的文字改写得{更通俗 / 更正式 / 更简洁}。
要求：
- 保持原意和所有关键信息，不增不减观点
- {术语第一次出现用一句话解释}
- 直接输出结果，不要说明你改了什么

参考这种风格：{一小段范例}

原文：
"""
{input}
"""
```

**翻译额外注意：**
- 指明**语气和场景**（口语对话 vs 正式文档，差别很大）
- **专有名词 / 术语**给个对照表或要求"保留原文 + 括号译名"
- 要求"符合目标语言习惯"，而不是逐字直译

**注意点（通用）：**
- 风格类需求**给范例最有效**（[6.3](./reasoning)），一段示范胜过"要优雅、要地道"
- 用低温保稳定；要多个候选版本时才调高

❌ "翻译这段话" → 不知道你要正式还是口语、术语怎么处理
✅ 指明场景语气 + 术语规则 + 给一句风格范例

## 四件套的共性

| 维度 | 经验 |
|-----|------|
| 客观性 | 都有相对标准 → 往"稳定可解析"使劲，低温 |
| 范例 | 分类/改写靠 Few-shot 定边界和风格 |
| 防加戏 | 抽取/摘要都要强调"只基于原文、不编造" |
| 结构 | 抽取给 schema、摘要给要点数，比给字数管用 |
| 升级 | 量大、要求高且固定 → 从堆提示升级到 [微调](/ch5-deep-dives/finetuning-cases) |

---

## 🛠️ 实战练习：把一个信息处理任务模板化

挑你常做的一件（如把用户反馈分类、从邮件抽取要点）：

1. 按本节对应模板写一版，补上 schema/类别定义/范例
2. 故意喂一个边界输入，看分类/抽取稳不稳
3. 加一条易混 Few-shot 范例，再试，看是否掰正
4. 存成可复用模板（变量用 `{占位符}`）

**期望结果**：你手上多了几个能直接套的信息处理模板，而不是每次从零想。

---

## 📌 关键结论

1. 信息处理四件套有客观标准，提示往"稳定、可解析、低温"使劲
2. 分类：类别定义清晰互斥 + 易混 Few-shot + 留"其它" + 只输出类别
3. 抽取：给 schema + 缺失填 null + 不编造 + 强制 JSON + 解析兜底
4. 摘要：指定长度/角度 + 强调忠实原文（最怕加戏）+ 给结构而非字数
5. 改写/翻译：给风格范例 + 指明场景语气 + 术语规则；量大固定可升级到微调
